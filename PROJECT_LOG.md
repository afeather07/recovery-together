### 2026-08-04 — Fixed production bug: "Room not found" traced to missing base table GRANTs
Aaron's live click-through test of the deployed onboarding flow hit "Room not found. Go back." Diagnosis via Supabase logs: `POST /rest/v1/profiles`, `POST /rest/v1/profile_private`, and `GET /rest/v1/rooms` all returned 403, with the underlying Postgres error literally `permission denied for table X` — not an RLS filter returning zero rows, but a hard privilege failure that happens *before* RLS is even evaluated. Found the root cause in the Postgres logs: an `alter default privileges ... revoke ...` statement had run against `anon`, `authenticated`, and `service_role` on the `public` schema before the app schema was ever created, stripping the base-level table grants Supabase normally provisions automatically. `supabase/schema.sql` only ever contained `enable row level security` and `create policy` statements, correctly assuming those defaults would exist — an assumption that had been invalidated for this project. Fix: applied a migration (`restore_base_table_grants`) explicitly granting `SELECT`/`INSERT`/`UPDATE` to `authenticated` and `SELECT` to `anon` on the tables each actually needs, plus full privileges back to `service_role` (needed for the admin view and any future service-role work, even though it bypasses RLS — the base grant is still required). Verified via `information_schema.role_table_grants` that every expected grant is now present. Mirrored the same GRANT statements into `supabase/schema.sql` so a fresh environment built from that file won't hit this again. Awaiting Aaron's retest of the full onboard -> room -> post -> reply -> report flow to confirm end-to-end.

### 2026-08-03 — Platform decision: Next.js + Supabase + Vercel
Compared against the required priorities (2–4 day MVP, mobile responsiveness, minimal founder configuration, portability, safe auth/DB, realtime, ability for Claude to continue implementation across sessions, low dead-end-rebuild risk):
- **Lovable + Supabase** — fastest to a visual demo, but optimizes for CRUD/dashboards, not custom realtime chat with row-level anonymity rules; generated code is harder for a second agent session to extend precisely.
- **Replit Agent** — low founder configuration, but a different agent's project conventions make handing continued implementation back to Claude across sessions harder.
- **Next.js + Supabase + Vercel** — plain, ordinary code, no proprietary format to fight. Supabase gives Postgres + Auth + Realtime + RLS as core primitives. Lowest dead-end-rebuild risk. **Selected.**

Built and verified locally (`npm run build`, 0 errors) before any credentials existed. Static prototype preserved at `legacy-static-prototype/`, not deleted.
